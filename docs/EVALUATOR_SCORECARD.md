# RAJ-KRISHI DRONE GRID — Evaluator Scorecard

This scorecard converts the Rajasthan Innovation Challenge evaluation lens into observable product evidence. It is deliberately written as a judge-facing checklist: every claim should be demonstrable in the repository, prototype or pilot plan.

## 1. Problem solving / innovation

**Problem:** Rajasthan does not merely need more drones. It needs a way to make authorised drone capacity universally reachable, affordable for fragmented smallholders, operationally compliant, and accountable to public spending.

**Observable evidence**
- Demand Density Engine converts fragmented requests into executable acre-service missions.
- Universal Service Coverage detects low-reach blocks and bundles them into a service obligation.
- Coverage Contract Engine can apply Department-configured viability-gap support per verified acre-service.
- Universal Reach Index gives reason-coded access scores instead of opaque rankings.
- Mission Compliance + Agronomic Application Passport prevents generative AI from overriding deterministic rules.

## 2. Business use case / USP / vision

**USP:** a vendor-neutral state orchestration layer above existing government and market capacity — not another drone marketplace or OEM fleet app.

**Observable evidence**
- One console federates Drone Didi/FPO/CHC/private providers.
- Government systems remain authoritative through explicit adapters.
- Proof-of-Service binds payment eligibility to service evidence.
- Service architecture is designed to scale from spraying to scouting, mapping and departmental extension campaigns.
- Long-term vision: every agricultural plot is serviceable by the nearest compliant network when agronomically and operationally appropriate.

## 3. Technical feasibility / interoperability / future readiness

**Observable evidence**
- Functional GIS-first Next.js prototype.
- Live public IMD gateway with graceful fallback.
- Explicit AgriStack/UFSI contract boundary.
- eGCA/Digital Sky compliance adapter; no fabricated approval API.
- Deterministic mission state machine and evidence model.
- Offline SUTRA ID Edge is optional, so weak-connectivity resilience does not create proprietary hardware lock-in.
- Optional FarmGraph adapter creates a Sense → Decide → Act → Verify loop without pretending it is state infrastructure.

## 4. Product roadmap / time to market

**90-day controlled pilot**
- Days 0–30: orchestration, policy packs, approved adapters, provider/RPC onboarding.
- Days 31–60: field execution in representative operating archetypes; service evidence and settlement sandbox.
- Days 61–90: before/after metrics, coverage-gap closure, capacity forecast, district command and state-scale plan.

**No core pilot budget is reserved for purchasing a new fleet.** The premise is to activate suitable existing authorised public/private capacity first.

## 5. Team ability / delivery credibility

Evaluation evidence should focus on delivered artefacts rather than biography:
- functioning product surface;
- integration truth matrix;
- documented architecture and authority boundaries;
- source register;
- build gate;
- 90-day backlog and acceptance matrix;
- previous Syntheon government-tech / edge-AI artefacts used only where directly relevant (e.g. SUTRA offline field operations, FarmGraph agricultural intelligence).

## 6. Addressable market / ROI / affordability

The immediate public-value unit is **verified acre-service**, not app transactions or drone sales.

Pilot ROI is measured through:
- lower mobilisation cost per acre in clustered routes;
- increased productive acres per drone/day;
- reduced idle asset days;
- improved service response in low-reach blocks;
- fewer unsupported/duplicate settlement claims;
- better targeting of RPC training and logistics capacity.

State-scale architecture can extend to other farm-service classes without replacing Farmer Registry, DGCA or treasury authority.

## 7. Financial proposal / best value

Indicative controlled-pilot ask: **₹74.80 lakh**.

Value-for-money principles:
- no core drone procurement;
- reuse authoritative digital rails;
- reuse suitable authorised fleet capacity;
- configuration-driven policies instead of bespoke per-district builds;
- measurable acceptance gates;
- open interfaces and exportable evidence to reduce lock-in.

## Non-negotiable credibility rules

1. Demo operating counts are labelled synthetic.
2. Only verified public/authorised integrations may be labelled live.
3. AI never waives regulation or agronomic policy.
4. Public support remains Department-configured; the product does not invent entitlement policy.
5. Government finance systems remain settlement authority.
6. No yield-improvement guarantee without controlled measurement.
7. Every score used for prioritisation exposes factors, weights and reason codes.
